# Ціна доставки в модулі доставки

Ціна доставки в замовленні — гроші магазину, тому браузеру вона не довіряється.
Документ про те, як модуль доставки (тип `MODULE_TYPE_DELIVERY`) може змінювати
ціну доставки і що для цього обов'язково, а що — на вибір.

## Як ціна потрапляє в замовлення

Під час оформлення (`CartController`) ядро викликає
`DeliveriesHelper::prepareDeliveryPriceInfo($delivery, $order)`:

1. Ядро рахує ціну з налаштувань способу доставки в адмінці: `price`, якщо сума
   кошика менша за `free_from`, інакше 0.
2. Ланцюгові розширення модулів можуть змінити `delivery_price` у результаті.
3. **Страховка ядра:** від'ємна, нечислова чи нескінченна ціна після всіх
   розширень замінюється ціною з адмінки, у лог — `a module returned an invalid
   delivery price`.
4. `updateDeliveryPriceInfo` пише ціну в замовлення, `updateTotalPrice` додає її до
   суми (якщо доставка не оплачується окремо).

Модулю, якому досить ціни з адмінки (самовивіз, кур'єр за фіксовану ціну, модуль, що
лише додає поля доставки), нічого з цього не треба: він не реєструє розширення
`prepareDeliveryPriceInfo` зовсім.

## Обов'язково, якщо модуль змінює ціну доставки

1. **Не читати ціну з форми.** Поле ціни в кошику (`*_delivery_price`) — лише для
   показу. Під час оформлення ціну береш із розрахунку сервера, ніколи з
   `$request->post(...)`. Це перевіряє `tests/Security/DeliveryPriceFromFormTest`.
2. **Змінювати ціну лише своїм способам доставки.** Перевірка — за `module_id`
   способу, а не за прапорцем із форми:

   ```php
   public function setCartDeliveryPrice($result, $delivery, $order)
   {
       if ((int)$delivery->module_id !== (int)$this->module->getModuleIdByNamespace(__CLASS__)) {
           return ExtenderFacade::execute(__METHOD__, $result, func_get_args());
       }
       // ...
   }
   ```

3. **Поважати безкоштовну доставку з адмінки.** Ціну ставиш лише для платного
   способу (`$delivery->paid`) і коли сума не досягла `free_from`
   (`$delivery->free_from > $order->total_price`) — інакше лишаєш результат ядра.
4. **Не знаєш ціни — нічого не став.** Розрахунку немає чи він не підходить — не
   чіпай `$result['delivery_price']`, лишиться ціна з адмінки. Запиши попередження в
   лог, щоб було видно, як часто так буває.
5. **Повертати результат через `ExtenderFacade::execute`**, як будь-яке розширення
   (див. [extenders.md](extenders.md)).

## На вибір

- **Показувати ціну в кошику до оформлення** (AJAX-розрахунок, як `ajax/np/calc`).
  Потрібно, лише якщо ціна залежить від міста, ваги тощо.
- **Пам'ятати розраховану ціну, щоб узяти її під час оформлення.** Найпростіший
  спосіб мати при оформленні ту саму ціну, що бачив покупець, без повторного
  запиту до API служби доставки. Як це зроблено в NovaposhtaCost — нижче.
- **Перераховувати ціну на сервері під час оформлення** замість запам'ятовування.
  Точніше, але оформлення тоді залежить від доступності API служби доставки.
- **Окремий прапорець способу оплати** (наприклад, післяплата), від якого
  залежить ціна, — тоді він входить у параметри розрахунку.

Модуль, який нічого з цього не робить, просто не змінює ціну: покупець платить ціну
з адмінки. Так працюють Meest і Ukrposhta там, де вони встановлені.

## Запам'ятовування ціни: як у NovaposhtaCost

Логіка живе в самому модулі, щоб модуль був самодостатнім і працював і на стоковій
OkayCMS. Для свого модуля скопіюй клас і заміни назви.

- `Helpers/NPDeliveryQuoteHelper.php` — сесійне сховище:
  - `remember(string $scope, array $context, object $cart, float $price)` — після
    розрахунку. Від'ємну чи нескінченну ціну не приймає.
  - `find(string $scope, array $context, object $cart): ?float` — під час
    оформлення. Повертає ціну лише якщо збіглися спосіб доставки (`$scope`),
    параметри (`$context`) і склад кошика (варіанти, кількість, сума); інакше `null`.
- `Helpers/NPDeliveryQuote.php` — **одне** місце, де записано, від чого залежить
  ціна: `scope($deliveryId)` і `context($cityRef, $redelivery)`. Розрахунок і
  оформлення будують параметри через нього, тож не можуть розійтись.
- `Controllers/NovaposhtaCostController::calc` — після успішного розрахунку для
  кошика (не для замовлення в адмінці) викликає `remember(...)` з `$cart->get()`.
- `Extenders/FrontExtender::setCartDeliveryPrice` — перевіряє `module_id`, `paid`,
  `free_from`, викликає `find(...)` з параметрами з форми й `$this->cart->get()`;
  `null` — попередження в лог і ціна з адмінки.

Параметри з форми (місто, відділення) тут безпечні: від них залежить лише, **яку**
збережену ціну шукати. Підставивши інше місто, покупець просто не знайде збігу й
отримає ціну з адмінки.

Що входить у `context`: усе, від чого залежить ціна, крім кошика (кошик хелпер
додає сам). Забудеш параметр — покупець зможе розрахувати дешевший варіант і
оформити дорожчий з тією самою ціною.

## Тести

- `tests/Security/DeliveryPriceFromFormTest.php` — жоден модуль не читає ціну з POST;
  NovaposhtaCost ставить ціну лише для свого `module_id` і лише з розрахунку; модулі
  без серверного розрахунку (Meest і Ukrposhta, де вони є) ціну не змінюють.
- `tests/Helpers/DeliveryPriceGuardTest.php` — страховка ядра.
- `tests/Modules/OkayCMS/NovaposhtaCost/NPDeliveryQuoteHelperTest.php` — збіг і
  незбіг параметрів, кошика, способу доставки; від'ємна ціна.

Новий модуль, що змінює ціну, додай у провайдер `extenders()` тесту
`DeliveryPriceFromFormTest`.
