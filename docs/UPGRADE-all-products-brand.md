# Оновлення: індексація фільтра за брендом на «всіх товарах» і сторінці бренду

Стосується всіх, у кого відкриті адреси `/all-products/brand-x`. Дій не потрібно: поки нові
налаштування не змінені, сторінки віддають ті самі canonical і robots, що й раніше.

## Навіщо

`/all-products/brand-x` показує ті самі товари, що й сторінка бренду `/brand/x`. Досі її
canonical і robots брались із налаштувань «На сторінці результатів фільтрації за брендом»,
спільних із категоріями (`/catalog/x/brand-y`). Закрити дубль можна було лише разом із
фільтрами категорій, які варто індексувати.

## Що додано

«Налаштування індексації» мають рядок «На сторінці всіх товарів із фільтром за брендом»
в обох колонках:

| Налаштування | Значення |
| --- | --- |
| `canonical_all_products_brand` | як для категорії (за замовчуванням), на сторінку бренду, на всі товари без бренду, на себе, відсутній |
| `robots_all_products_brand` | як для категорії (за замовчуванням), `index,follow`, `noindex,follow`, `noindex,nofollow` |

«Як для категорії» — це `0` або відсутній рядок у `settings`, тому міграції немає: на
наявних інсталяціях діє рівно старе правило `canonical_category_brand` / `robots_category_brand`.

## Коли canonical веде на сторінку бренду

Значення «на сторінку бренду» (`CANONICAL_BRAND_PAGE`) діє, лише коли адреса зводиться до
сторінки бренду:

- у фільтрі рівно один бренд, без властивостей і без `filter-*`;
- це не пошук (`?keyword=` завжди `noindex,nofollow`, canonical лишається як був);
- бренд видимий (прихований віддає 404 на `/brand/x`).

Хвіст адреси переноситься за звичними правилами: сортування відкидається, ціна лишається,
сторінка — за «пагінацією результатів фільтрації». Наприклад, за «вказує на поточну сторінку»
`/all-products/brand-x/page-2` → `/brand/x/page-2`, за «на першу сторінку» → `/brand/x`.
Вимкнений page-all дає `/brand/x`. Якщо налаштування пагінації прибирає бренд або canonical,
або фільтр глибший за дозволене, діє правило категорії. Будь-яка інша адреса (кілька брендів,
бренд разом із властивістю чи `filter-*`) теж бере правило категорії.

Robots налаштовуються окремо й не залежать від canonical. Google радить не ставити
`noindex` на сторінку, чий canonical веде деінде, тож для «на сторінку бренду» robots
залишайте `index,follow` або «як для категорії».

## Що поряд

- `hreflang` у темах, що виводять його лише на канонічній адресі, на склеєних сторінках
  зникає; `og:url` іде за canonical.
- `rel="prev"/"next"` лишаються на `/all-products/brand-x/page-N`.
- Карта сайту адрес `/all-products/brand-*` не містить і не змінюється.

## Для розробників

- `CanonicalHelper::getAllProductsCanonicalData()` і
  `CanonicalHelper::getAllProductsBrandPageCanonicalData()`,
  `MetaRobotsHelper::getAllProductsRobots()` — розширювані через `ExtenderFacade`.
- `getCatalogCanonicalData()` і `getCatalogRobots()` працюють як раніше; `ProductsController`
  тепер викликає нові методи.
- `setParams()` обох хелперів отримав необов'язковий останній аргумент.

## Посилання на категорії зі сторінки бренду

Сторінка бренду показує категорії бренду з посиланнями `/catalog/<категорія>/brand-<бренд>`.
Якщо в категорії лише цей бренд, а «Приховувати поодинокі фільтри» (`hide_single_filters`) увімкнено,
`CategoryController` відповідає на таку адресу 404. Тепер `BrandsHelper::assignBrandFilterProcedure()`
передає в шаблон `$catalog_categories_without_brand_filter` (ключі — id таких категорій), а
`features.tpl` тем із комплекту дає для них звичайну адресу категорії.

- Рахується одним запитом на весь список: `FilterHelper::getCategoriesWithoutBrandFilter()`
  через `BrandsEntity::findCategoriesBrandsIds()`.
- Фільтр брендів категорії (`FilterHelper::getCategoryBrandsFilter()`) і правило приховування
  єдиного бренду спільні з `CategoryController` і `getBrands()`, тож позначка й 404 не
  розходяться. Розширення, що змінює результат `getBrands()`, у позначку не потрапляє.
- Тема, яку не оновили, не використовує змінну й лишає старі посилання: нічого не ламається.
  Щоб виправити свою тему, додайте перед гілкою з `filtersUrl=['brand' => $brand->url]`:

```smarty
{elseif isset($catalog_categories_without_brand_filter[$c->id])}
    href="{url_generator route="category" url=$c->url}"
```
