# Злиття й перейменування значень властивості

Команда `features:merge-values` зливає значення однієї властивості за JSON-картою і перейменовує
їх. Без `--apply` вона лише показує, що зробить. З `--apply` виконує все в одній транзакції й перед
комітом звіряє стан бази з планом; помилка чи розбіжність відкочує все.

```bash
php ok features:merge-values --map=<шлях до JSON>            # план, нічого не змінює
php ok features:merge-values --map=<шлях до JSON> --apply    # застосувати
```

Код: `backend/Helpers/BackendFeaturesValuesMergeHelper.php`,
`Okay/Core/Console/Commands/Features/FeaturesMergeValuesCommand.php`.

## Що робить

**Злиття** (`merge` → `into`). Ціль зберігає свій id, тексти й translit у кожній мові, тож її адреси
фільтрів не змінюються. Товари джерел переходять на ціль. Товар, що вже мав ціль, лишається з одним
рядком, дубля немає.

- Без `categories` злиття глобальне. Переносяться всі товари, джерело видаляється разом із мовними
  рядками й псевдонімами (`FeaturesValuesEntity::delete()`, як в адмінці).
- З `categories` переносяться лише товари, що лежать хоча б в одній із названих категорій. Джерело
  лишається з рештою товарів. Товар із кількох категорій переїжджає цілком, і план показує, в яких
  ще категоріях він лежить («Ці товари лежать і поза областю»).

**Перейменування** (`rename` → `to`). Міняє текст у названих мовах (ключ — мітка мови), translit і
адреса не змінюються. Мови, яких немає в `to`, лишаються як були.

**Редиректи** (`redirects`) потрібні для адрес джерел, які вже є в пошуку. Ядро їх не зберігає, а
передає в `BackendFeaturesValuesMergeHelper::storeRedirects()` модулю редиректів (розширення
повертає кількість збережених правил). Якщо жоден модуль їх не прийняв, `--apply` з редиректами
відкочується з помилкою. Порожній список нічого не робить.

Карта перевіряється до першого запису. Кожне значення задане парою id + поточний текст, і якщо текст
у базі інший (значення перейменували, id чуже, властивість інша), команда відмовляє й нічого не
змінює. Так само вона відмовляє, коли категорія не збігається з адресою, мова невідома або правило
згадує значення, яке видалило попереднє правило.

### Формат карти

```json
{
  "feature_id": 3,
  "rules": [
    {"note": "дубль", "merge": [{"id": 512, "value": "Синій"}], "into": {"id": 64, "value": "Синій"}},
    {"rename": {"id": 70, "value": "Блакитний"}, "to": {"ua": "Світло-синій", "en": "Light blue"}},
    {"merge": [{"id": 81, "value": "Темний"}], "into": {"id": 64, "value": "Синій"},
     "categories": [{"id": 12, "url": "jeans"}]}
  ],
  "redirects": [{"from": "/catalog/jeans/color-temnij", "to": "/catalog/jeans/color-sinij"}]
}
```

Правила виконуються по черзі. План кожного кроку враховує попередні.

## Що ще посилається на id значень

| Де | Що відбувається |
| --- | --- |
| `products_features_values`, `lang_features_values`, `features_values_aliases_values` | переносить або видаляє команда |
| умови фідів `OkayCMS/Feeds` (`feature_value`) | зберігають id значення. Умова з видаленим джерелом більше нічого не відбирає — перевірте умови фідів перед глобальним злиттям |
| SEO-шаблони фільтрів, посадкові «бренд + властивість» | зберігають id властивості, а не значення; посадкові рахуються наживо |
| таблиці модулів | модуль, що зберігає id значень у себе, розширює `mergeValues()` або `renameValue()` |

Розширення модулів реєструються в їхньому `init()`, тож команда спершу ініціалізує модулі.

## Порядок дій

1. Зробіть резервну копію таблиць `features_values`, `lang_features_values`,
   `products_features_values`, `features_values_aliases_values`, `lang_features_aliases_values`
   (і таблиці модуля редиректів, якщо карта їх має) **до** запуску — команда відкочує лише власну
   невдалу транзакцію. Потім пробний прогін без `--apply`, перевірка плану, `--apply`.
2. Скиньте кеш: `compiled/`, `backend/design/compiled/`, `cache/` і кеш модуля, якщо він кешує товари
   (наприклад, Redis).
3. Перевірте сторінки фільтрів цілей: кількість товарів має збігатися з базою. Адреси джерел, що
   видалено, віддають 404, якщо для них немає редиректу.

Сторінка фільтра, у категорії якої значення більше не має товарів (після злиття лише за
категоріями), віддає 200 з порожнім списком — так само, як будь-яке значення без товарів у
категорії.
